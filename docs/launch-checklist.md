# 上线检查清单

把这个 demo 变成能真实营业的小程序，按顺序过一遍。带 ⚠️ 的是最容易卡住的。

## 一、账号与资质

- [ ] 注册小程序账号（mp.weixin.qq.com，个人主体免费，**但开不了微信支付**）
- [ ] 要收款 → 企业或个体工商户主体 + 300 元/年认证
- [ ] 拿到 AppID，填进 `project.config.json` 或导入时替换
- [ ] ⚠️ 服务类目选对：餐饮点单要「餐饮服务」相关类目，通常需要**《食品经营许可证》**
- [ ] 设置小程序名称、头像、简介（名称唯一，先想好备选）
- [ ] 添加开发者：把实际开发者的微信号加进「成员管理」

## 二、功能补全

- [ ] 订单要落到店里：接云开发或自建后端（见 `docs/cloud-migration.md`）
- [ ] 菜单可维护：店长能改价、上下架（demo 已实现，上云后要落库）
- [ ] 订单状态真实化：店长真实接单，而不是时间模拟（demo 已用状态机，可直接用）
- [ ] 用户身份：`wx.login` 换 openid，订单归属到人
- [ ] 商品图片：换成真实图，走云存储或 CDN
- [ ] 订阅消息：做好通知顾客取餐（需在公众平台申请模板）
- [ ] 提交订单幂等：防止连点造成重复下单

## 三、域名与网络

- [ ] ⚠️ 所有请求域名必须是 **HTTPS**
- [ ] 在「开发管理 → 服务器域名」配 `request` 合法域名（每月只能改 5 次）
- [ ] 开发阶段可在详情设置里勾「不校验合法域名」，**但上线前必须关掉**

## 四、备案与合规

- [ ] ⚠️ **ICP 备案**：2023 年 9 月起，小程序上线前必须完成备案（免费，1–2 周）
- [ ] 隐私协议：如果收集手机号、位置等信息，必须在小程序内提供隐私政策并在公众平台配置
- [ ] 本 demo 不收集个人信息（无 `wx.login`、无手机号、无位置），所以无需隐私弹窗；
      一旦加了登录或定位，这一项必须补

## 五、支付

- [ ] 企业主体 + 微信支付商户号
- [ ] 后端统一下单拿支付参数，前端 `wx.requestPayment`
- [ ] ⚠️ 订单状态以**服务端支付回调**为准，不要只信前端 success
- [ ] 退款流程与对账

## 六、提审前自检

- [ ] 真机跑一遍完整链路：点单 → 支付 → 取餐
- [ ] 断网、后端挂掉时的兜底提示（不能白屏、不能静默失败）
- [ ] 空态：无订单、无商品、无搜索结果
- [ ] 主包体积 < 2MB，超了要分包
- [ ] 删除调试代码与 `console.log`

## 七、常见驳回原因

| 驳回原因 | 处理 |
|---|---|
| 类目与功能不符 | 按实际业务选类目，餐饮必须有食品经营许可证 |
| 缺少必要资质 | 提前准备营业执照、许可证 |
| 诱导分享 / 诱导关注 | 去掉「分享得优惠」这类文案 |
| 页面空白或打不开 | 检查域名白名单与 HTTPS |
| 未备案 | 先完成 ICP 备案再提审 |
| 涉及收集个人信息但无隐私政策 | 补隐私协议与授权弹窗 |
